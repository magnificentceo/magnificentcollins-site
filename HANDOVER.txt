2. ADDING A NEW SONG
------------------------------------------------------------
  1. Save the square cover art into assets/covers/ with a simple name, for example
     assets/covers/new-song.jpg (lowercase, dashes instead of spaces).
  2. Open data/releases.js in Notepad (or any text editor).
  3. Find the line   "releases": [
     Right under it, paste a new block like this one (keep the comma at the end):

    {
      "id": "new-song",
      "title": "New Song",
      "date": "2027-03-14",
      "cover": "assets/covers/new-song.jpg",
      "links": [
        { "service": "Spotify", "url": "PASTE THE SPOTIFY TRACK LINK" },
        { "service": "Apple Music", "url": "PASTE THE APPLE MUSIC LINK" },
        { "service": "YouTube Music", "url": "PASTE THE YOUTUBE MUSIC LINK" },
        { "service": "YouTube", "url": "PASTE THE YOUTUBE LINK" },
        { "service": "All platforms", "url": "PASTE THE HYPERFOLLOW LINK" }
      ]
    },

     Only add services you actually have a working link for. Delete any line you do not have.
     Every line inside "links" ends with a comma except the last one.
  4. To make it the featured song at the top, change   "featured": "i-dey"   to the new id,
     for example   "featured": "new-song"
     Optional: change "accent" (also in data/releases.js) to a bright color from the new cover.
     It colors the main Listen button, the "Latest release" label and the small underlines.
     The current gold #E3B23C comes from the I Dey cover.
  5. The page sorts songs by date and builds the year groups by itself.
  6. To update the page preview image for link sharing, open index.html and change the two
     lines that mention assets/covers/i-dey.jpg to the new cover file.

  Background photo: assets/artist/stage.jpg (your stage photo, unchanged). To use a different
  photo later, save it with the same name in the same folder. A tall photo with a dark
  background works best, since the page text sits on top of it.

  Button icons: the platform icons are in assets/icons/. Spotify, YouTube, Amazon Music, Deezer,
  Instagram, TikTok and Facebook come from Font Awesome Free (CC BY 4.0; the small credit line at
  the bottom of the page is required by that license, so keep it). Apple Music, YouTube Music,
  TIDAL, Audiomack, Pandora and iHeart come from Simple Icons (CC0, version 16.36.0).
  Boomplay and Anghami come from Arcticons (CC BY-SA 4.0), with the line weight increased so
  they show at button size; that license also needs the credit line. Amazon Music uses the
  general Amazon mark.
  To add an icon: put the .svg in assets/icons/ and add a line to the ICONS list in app.js.

  Button colors: each platform's color is set in app.js, in the list near the top called BRAND.
  Use the service name exactly as written there (for example "YouTube Music"). A new service
  that is not in that list still works; it just gets a plain gray button until you add its color.

  Hiding a link without deleting it: add  "hidden": true  to that link, like
    { "service": "Pandora", "url": "https://...", "hidden": true }

2b. LYRICS AND COMMENTS
------------------------------------------------------------
  Lyrics, the easy way (recommended): one plain text file per song in site/lyrics/,
  named after the song's id, for example site/lyrics/i-dey.txt or site/lyrics/waka.txt.
  Type or paste the words exactly as you want them shown, with normal line breaks and a
  blank line between verses. On GitHub: open the repository, click "Add file", then
  "Create new file", type site/lyrics/i-dey.txt as the name, paste the lyrics, and click
  "Commit changes". The Lyrics panel appears under that song within a minute or two.
  Song ids: i-dey, i-get-backing, tomorrow-can-wait, my-mouth, never-stagger, waka,
  the-way-i-know-how. To remove lyrics, delete the file.

  Lyrics, the older way: each song in data/releases.js has a "lyrics" line. Put the words between the
  quotes. Write \n where a new line starts and \n\n for a blank line between verses.
  A song with "lyrics": "" shows no Lyrics panel.

  Comments and reviews use Cusdis (https://cusdis.com), free plan: 1 website,
  100 approved comments a month. Visitors do not need an account. Nothing appears on your
  site until you approve it in your Cusdis dashboard.
  Setup (one time, needs your sign-in):
    1. Sign up at https://cusdis.com and add a website (any name, for example
       "Magnificent Collins").
    2. Open the website's settings or embed code and copy the App ID (a long code with
       dashes).
    3. In data/releases.js, paste it between the quotes after "appId", then publish the
       update (section 3).
  Each song gets its own comment thread. Cusdis can show one comment box at a time, so a
  visitor opens one song's comments at a time.
  To approve comments: sign in at https://cusdis.com and open your website's dashboard.
  Turn on email notifications there so you know when a comment is waiting.

6. SECURITY (reviewed November 7, 2026)
------------------------------------------------------------
  The site is static: no server code, database, logins, admin pages, file uploads or
  forms of its own. Most "vibe coding" security checklists (RLS, SQL queries, password
  hashing, webhooks, admin routes, rate limiting, server-side secrets) do not apply,
  because there is nothing on the site for them to protect.

  What is in place:
  - site/_headers: security headers Cloudflare sends with every page. They block
    cross-site scripting from other sites, stop other sites from embedding your page,
    force secure https connections, and turn off camera, microphone and location access.
  - No secrets anywhere in the files. The Cusdis App ID is public by design.
  - .gitignore: GitHub will never save .env files, keys or other secret files, even
    by accident.
  - Nothing is written to logs, and saves to GitHub use your private no-reply address
    (magnificentceo@users.noreply.github.com) instead of your personal email.
  - All song, title and lyric text is inserted as plain text, never as code.
  - Every outside link opens safely in a new tab (rel="noopener").
  - No outside code libraries, so there is nothing to keep updated.

  BEFORE TURNING ON COMMENTS: the Content-Security-Policy line in site/_headers blocks
  outside scripts. Cusdis must be added to it first, or the comment box will not load.
  Ask Claude to do this together with adding your App ID.

  The biggest risk is your accounts, not the code. Turn on two-factor authentication
  (an authenticator app) for: Cloudflare (domain and hosting), GitHub (site files),
  your Gmail (password resets for everything else) and later Cusdis.
